## Where a module's files go

Take the Fees module (`fees`). Its resource `fee-vouchers` produces:

| Layer | File |
|---|---|
| Contract | `packages/contracts/src/modules/fees/fee-vouchers.contract.ts` |
| Table | `packages/db/src/schema/fees/fee-vouchers.table.ts` |
| DB-service | `packages/core/src/modules/fees/fee-vouchers.db-service.ts` |
| Service | `packages/core/src/modules/fees/fee-vouchers.service.ts` |
| Pure rules | `packages/core/src/modules/fees/fees.rules.ts` (calculations with no database) |
| Jobs | `packages/core/src/modules/fees/fees.jobs.ts` |
| Routes | `apps/web/app/api/v1/fee-vouchers/route.ts`, `…/[id]/route.ts`, `…/[id]/<action>/route.ts` |
| API-service | `packages/api-client/src/modules/fees/fee-vouchers.api-service.ts` |
| Hooks | `packages/hooks/src/modules/fees/fee-vouchers.hooks.ts` |
| Screens | `apps/web/src/features/fees/…` and pages under `apps/web/app/(app)/school/fees/…` |
| Tests | `tests/api/fees/fee-vouchers.test.ts`, `tests/e2e/school/fees.spec.ts` |

Each package has one `index.ts` per module folder that re-exports its files, and the package root re-exports every module.

## Package dependency graph

```
contracts ◄── db ◄── core ◄── apps/web (api routes)
    ▲                            │
    ├──── api-client ◄── hooks ◄─┤ (screens)
    └──── ui ◄───────────────────┘
core ◄── worker
```

- `contracts` depends on nothing but `zod`.
- `api-client`, `hooks` and `ui` must never import `db` or `core`. This is what lets them run in the browser and, later, in the mobile apps.

## Workspace packages are used as source

Internal packages are not built to `dist`. Each `package.json` points `exports` at `./src/index.ts`, and `apps/web/next.config.ts` lists them in `transpilePackages`. Tests and scripts run through `tsx` and Vitest, which read TypeScript directly. This removes a build step and keeps "go to definition" pointing at real source.

## Scripts (root `package.json`)

| Command | Does |
|---|---|
| `pnpm dev` | Runs the web app |
| `pnpm worker` | Runs the job worker |
| `pnpm db:start` / `db:stop` | Starts or stops local Supabase |
| `pnpm db:env` | Writes `.env.local` from the running local stack; prints nothing secret |
| `pnpm db:generate` | Generates a migration from the table files |
| `pnpm db:migrate` | Applies migrations |
| `pnpm db:seed` | Loads seed data |
| `pnpm db:reset` | Empties the database, migrates and seeds |
| `pnpm db:studio` | Prints the addresses of Supabase Studio and the mail catcher |
| `pnpm db:verify-plan` | Compares the tables in code with the tables in this plan |
| `pnpm typecheck` | TypeScript across the workspace, including `tests/types` |
| `pnpm lint` | ESLint, including the layer-boundary rules |
| `pnpm test` | Unit, service and API tests (PGlite) |
| `pnpm test:db` | The same tests against the Docker Postgres |
| `pnpm test:e2e` | Playwright against the running app |
| `pnpm check` | `typecheck` + `lint` + `test` — the gate before any commit |
| `pnpm smoke` | Signs in as seeded accounts and calls the running app; the quickest proof that the whole stack is alive |
| `pnpm format` | Prettier over the code |
| `pnpm plan:check` | Validates this plan's cross-references and rebuilds its indexes |

## Path length on Windows

Keep the repository at a short path such as `C:\Users\<you>\Desktop\projects\takhti`. Some Node tools fail when a file's full path passes 260 characters, which a deep folder plus `node_modules/.pnpm/…` reaches quickly.
