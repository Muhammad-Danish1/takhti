# Adding a resource

A *resource* is one kind of record with an API: rooms, students, fee vouchers. This is the path every resource takes through the seven layers. `rooms` is the worked example; it was added by following these steps without changing a kernel file, and `branches` shows the same steps with named actions on top.

**Since Phase 2 began, the plain version of most resources already exists.** `pnpm scaffold:api` writes the contract, db-service, service, routes, API client and hooks of every resource whose planned routes are plain, and `pnpm scaffold` writes every table. So this guide is now mostly used in one of two ways: to **take over** a generated resource when it gets rules of its own (list its table under `handWritten` in `docs/plan/_tools/api-hints.mjs`, remove the "Generated by" header from its files, export them from each package's `index.ts`, then follow steps 1 and 3 to 8 below as edits rather than as new files), or to write a resource the generator leaves out (Wave 0, append-only tables, anything whose "add" needs a number or a total). Where the build stands is in [`docs/STATUS.md`](../STATUS.md).

Before you start, read the resource's module spec in [`docs/plan/10-modules/`](../plan/10-modules/). The spec's table, rules (`R-…`), permissions, routes and failure cases (`F-…`) are what you are implementing. If the code needs to differ from the spec, change the spec in the same piece of work.

## The eight steps

| # | Layer | File | Worked example |
|---|---|---|---|
| 1 | Contract | `packages/contracts/src/modules/<module>/<resource>.contract.ts` | [`rooms.contract.ts`](../../packages/contracts/src/modules/organisation/rooms.contract.ts) |
| 2 | Table | `packages/db/src/schema/<module>/<resource>.table.ts` | [`organisation.table.ts`](../../packages/db/src/schema/organisation/organisation.table.ts) |
| 3 | DB-service | `packages/core/src/modules/<module>/<resource>.db-service.ts` | [`rooms.db-service.ts`](../../packages/core/src/modules/organisation/rooms.db-service.ts) |
| 4 | Service | `packages/core/src/modules/<module>/<resource>.service.ts` | [`rooms.service.ts`](../../packages/core/src/modules/organisation/rooms.service.ts) |
| 5 | Routes | `apps/web/app/api/v1/<resource>/route.ts` and `[id]/route.ts` | [`rooms/route.ts`](../../apps/web/app/api/v1/rooms/route.ts) |
| 6 | API-service | `packages/api-client/src/modules/<module>/<resource>.api-service.ts` | [`rooms.api-service.ts`](../../packages/api-client/src/modules/organisation/rooms.api-service.ts) |
| 7 | Hooks | `packages/hooks/src/modules/<module>/<resource>.hooks.ts` | [`rooms.hooks.ts`](../../packages/hooks/src/modules/organisation/rooms.hooks.ts) |
| 8 | Tests | `tests/api/<module>/<resource>.test.ts` | [`rooms.test.ts`](../../tests/api/organisation/rooms.test.ts) |

Each file is small because the kernel does the repeated work. A layer imports only the layers above it in this table; ESLint refuses anything else.

### 1 · Contract

The shape of the API, written once and used by every other layer.

- Put the fields a person can type in one `fields` object. Build the entity, the create body and the update body from it.
- Use the primitives (`Name`, `Phone`, `Money`, `DateStr`, …) so a value is validated the same way everywhere.
- The create body lists required fields first and optional ones with `.optional()`. It may carry `id` so an offline device can make the id.
- The update body is `z.object(fields).partial().extend({ version: z.int() })`. Built from fields *without defaults*, so leaving a field out never resets it.
- `listQuery({ sortable, defaultSort, filters })` gives paging, search and sorting, and refuses a parameter it does not know.
- A status column gets a machine: `defineMachine({ active: ['inactive'], inactive: ['active'] })`.
- Finish with `defineResource({ name, path, entity, create, update, list })`. `name` is the permission prefix and the audit name.
- Add the module's permissions to `<module>.permissions.ts`, its settings to `<module>.settings.ts` and its events to `<module>.events.ts`, and list a new module in [`catalogue.ts`](../../packages/contracts/src/catalogue.ts).
- Export the new file from [`packages/contracts/src/index.ts`](../../packages/contracts/src/index.ts).

### 2 · Table

- Declare it with `table(...)` (never `pgTable`), spreading `baseColumns`, and `branchId: branchIdColumn()` for a branch-level table.
- Money is `paisa()`, a date is `dateStr()`, a moment is `timestamptz()`, a fixed list is `enumText(values)` with `...enumChecks('<table>', t)` in the extra config.
- Add every `Unique:` and `Index:` line of the spec. "Unique" means a partial unique index `where deleted_at is null`.
- A foreign key is `.references(() => other.id)`. Every foreign key column is indexed for you; mark a rare exception with `unindexed(...)` and say why.
- Add the policies for the table's scope: `orgScoped`, `branchScoped`, and the modifiers `familyRead`, `householdRead`, `selfOwned`, `capRestricted`.
- Register it: `registerTable(rooms, 'rooms', { module: 'M02', scope: 'branch' })`. The generated security tests cover it from that moment.
- Export the file from [`schema/index.ts`](../../packages/db/src/schema/index.ts), then:

```bash
pnpm db:generate --name <what-changed>
```

Read the generated SQL, then:

```bash
pnpm db:migrate
```

```bash
pnpm db:verify-plan
```

The last command compares the table with the plan: columns, types, allowed values and foreign keys.

### 3 · DB-service

`createDbService(table, { label, search, sort, filters })` gives `find`, `get`, `findMany`, `list`, `listCursor`, `insert`, `update`, `remove`, `restore`, `lock`, `count` and `exists`. It leaves out deleted rows, stamps who and when, and raises `version`.

- `sort` must have a column for every sortable name in the contract; a missing one is a compile error.
- `filters` turns the contract's filters into conditions. Add `branchFilter(ctx, table.branchId)` for a branch-level table.
- Queries only this module needs go in the same file, next to the generated ones (see [`branches.db-service.ts`](../../packages/core/src/modules/organisation/branches.db-service.ts)).

### 4 · Service

`createCrudService({ contract, db, ... })` wraps the db-service with the module switch, the permission check, the rules, the audit entry and the events.

- `actions` when a permission covers more than one operation (`rooms:update` creates, changes and deletes), or `false` to switch an operation off (a branch is never deleted).
- `rules.beforeCreate / beforeUpdate / beforeRemove`: one check per rule in the spec. Throw `rule('…')` with a sentence a person can act on; the transaction rolls back.
- `registerConstraintMessages({ rooms_name_uq: { message, field } })` so a duplicate says what is duplicated, under the right field.
- A named action (`deactivate`, `collect`, `approve`) is a function beside the generated ones: `assertCan`, load, check the machine with `assertTransition`, write through the db-service, `audit`.
- Something another module may forbid (deleting a room that a section uses) is a small registry the other module adds to, as `registerRoomUse` does. A module never imports a module that comes later.
- If the contract's create body does not fit the table, TypeScript demands `toInsert`. That is the contract and the table telling you they have drifted.
- Export the two files from [`packages/core/src/index.ts`](../../packages/core/src/index.ts).

### 5 · Routes

```ts
export const { GET, POST } = collectionRoutes(roomsContract, roomsService);
```

```ts
export const { PATCH, DELETE } = itemRoutes(roomsContract, roomsService);
```

Export only the methods the module's route table lists: the plan has no route that reads one room, so `GET` is left out. Then run `pnpm api:manifest` and `pnpm api:verify-plan`: the first writes the route into the manifest, the second fails if the plan does not have it or gives it another permission.

A named action is its own file, `[id]/<verb>/route.ts`, built with `defineRoute({ params, body, handler })`. Mark anything that must not happen twice `idempotent: true`. A route file contains no logic.

### 6 · API-service and 7 · Hooks

```ts
export const roomsApi = createApiService(roomsContract);
```

```ts
const crud = createCrudHooks(roomsContract, roomsApi);
export const useRooms = crud.useList;
```

Named actions get one line in the api-service and one small hook, as in [`branches.hooks.ts`](../../packages/hooks/src/modules/organisation/branches.hooks.ts). Export both files from their package's `index.ts`.

### 8 · Tests

Copy [`rooms.test.ts`](../../tests/api/organisation/rooms.test.ts). It calls the real Route Handlers as real seeded people. Cover, by name:

| Test | Proves |
|---|---|
| Create, read, list, update, delete | The happy path, in the shape of the contract |
| Each filter, each sort, search, paging | The list is wired correctly |
| One test per `R-…` rule and per `F-…` failure case | Named with the id from the spec |
| `403` for a role without the permission | Wall 1 |
| Another branch, another school | Wall 2, end to end |
| `422` with the right field names; `409 STALE` | Validation and lost-update protection |
| Audit entries | One per write, with only what changed |
| A failed request leaves nothing behind | One transaction per request |

Row-level security for the table needs no test of your own: [`rls.generated.test.ts`](../../tests/api/security/rls.generated.test.ts) probes every registered table. A table with a hand-written policy is marked `custom: true` and gets a section in [`custom-policies.test.ts`](../../tests/api/security/custom-policies.test.ts).

## Before you call it done

```bash
pnpm check
```

```bash
pnpm test:db
```

```bash
pnpm db:verify-plan
```

The first runs type-check, lint and every test on the in-process database. The second runs the tests again on the Docker Postgres, where real concurrency and the real server's behaviour show. The third confirms the table still matches its spec.

## Things that catch people out

- **One unit of work.** A function that already has a `ctx` passes it on. Opening `runAs` inside `runAs` is refused, because the inner transaction would not see the outer one's writes.
- **No clock.** Use `ctx.now` and `ctx.today`. A test fixes them with `freezeTime(...)`.
- **No arithmetic on money.** Use `percentOf`, `times`, `fraction`, `allocate` and `sum` from the kernel.
- **A family user may write a row and not read it back.** Audit entries, events and jobs are inserted without `returning`, and without naming index columns in `on conflict`, because either makes Postgres apply the table's read policy to the new row.
- **A table file must not be imported while it is still loading.** Reference another table lazily, `() => other.id`, and annotate the callback `(): AnyPgColumn =>` when two files reference each other.
